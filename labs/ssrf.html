SSRF 서버를 심부름꾼으로

"이미지 주소를 넣으면 미리보기를 보여주는" 기능 많죠? 이때 서버가 대신 그 주소에 접속해요. 공격자가 외부 주소 대신 서버 내부 주소를 넣으면, 바깥에선 못 보는 내부 비밀 정보를 서버가 대신 가져다 줍니다. 이게 SSRF예요.

모의 사이트 · "URL 미리보기 서비스"

🔗 이미지 URL 미리보기

🔓 어떤 주소든 서버가 그대로 접속합니다. 내부 주소도요!
🔒 내부 IP·메타데이터 주소를 차단 목록으로 막습니다.
server-internal-network
서버가 가져온 응답이 여기 표시됩니다.

🎯 공격 미션

외부 주소 대신 클라우드 서버의 비밀 정보 주소를 넣어보세요. (실제 AWS 서버의 내부 메타데이터 주소예요)

http://169.254.169.254/latest/meta-data/iam/security-credentials/

또는 내부 관리자 페이지를 노려보세요:

http://localhost:8080/admin/secret
왜 위험할까? 169.254.169.254 는 클라우드 서버 안에서만 접근되는 특수 주소로, 서버의 로그인 열쇠(액세스 키)가 들어있어요. 해커가 이걸 빼내면 회사의 클라우드 전체를 장악할 수도 있습니다. 실제 대형 유출 사고의 단골 원인이에요.

🔍 무슨 차이일까?

🔓 취약한 코드
# 사용자가 준 주소를 검증 없이 그대로 요청
response = requests.get(user_url)   # 내부 주소든 뭐든 다 감
return response.text
🔒 방어된 코드
# 내부망·메타데이터 주소를 막고, 허용 목록만 통과
host = urlparse(user_url).hostname
if is_private_ip(host) or host == "169.254.169.254":
    raise Error("내부 주소 접근 금지")
if host not in ALLOWED_DOMAINS:
    raise Error("허용되지 않은 도메인")
핵심 방어법
① 사설 IP 대역(10.x, 192.168.x, 127.x, 169.254.x) 차단
② 허용 목록(allowlist) 방식 — 믿을 수 있는 도메인만 통과
③ 클라우드 메타데이터는 IMDSv2(토큰 필요)로 전환
